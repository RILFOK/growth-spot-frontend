# Frontend — авторизация и 2FA

## Назначение
Frontend реализует авторизацию административной части сайта и поддерживает двухфакторную аутентификацию через TOTP.

Авторизационная логика используется в админ-панели и управляет входом, хранением сессии, повторной верификацией и выходом пользователя.

## Хранение авторизации
В `localStorage` сохраняются:
- `token`
- `admin_user`

`token` используется для авторизованных API-запросов, а `admin_user` хранит данные текущего пользователя для интерфейса и проверки прав доступа.

## Логика входа
Базовый сценарий входа выглядит так:
1. пользователь вводит email и пароль;
2. frontend отправляет `POST /auth/login`;
3. если `require2FA = true`, открывается второй шаг подтверждения;
4. если 2FA не требуется, пользователь входит сразу.

После успешной авторизации пользователь перенаправляется в административную часть приложения.

## 2FA
Во frontend поддерживается TOTP через Google Authenticator.

Пользователь может:
- пройти дополнительную проверку при входе;
- включить 2FA в настройках безопасности;
- отключить 2FA после подтверждения кодом.

### Используемые endpoint'ы
- `POST /auth/login`
- `POST /auth/verify-2fa`
- `POST /auth/enable-2fa`
- `POST /auth/disable-2fa`
- `GET /auth/me`

## Поведение при ошибке авторизации
Axios interceptor обрабатывает ответы backend со статусом `401`.

В этом случае frontend:
- очищает `localStorage`;
- сохраняет сообщение в `sessionStorage`;
- выполняет редирект на `/admin/login`.

Такой механизм используется для автоматического завершения сессии, если токен устарел, стал недействительным или больше не соответствует данным пользователя на backend.
## Особенности безопасного восстановления сессии

При перезагрузке страницы сохранённый JWT проверяется запросом `GET /auth/me`; роль из `localStorage` не считается подтверждённой, а административный интерфейс ожидает ответ сервера. При некорректном ответе сессия очищается. Неизвестная или отсутствующая роль не подменяется ролью `admin`.

TOTP-секрет существует в памяти компонента только во время подключения Authenticator и после успешного подтверждения очищается из состояния. Уже созданные прежней версией ключи `totp_secret_*` удаляются при запуске приложения; автоматический показ одноразового кода убран. Статус 2FA определяется ответом API.

**Ограничение текущей итерации:** JWT по-прежнему хранится в `localStorage` и потенциально доступен при XSS. Для реального развёртывания следует отдельно рассмотреть безопасные HttpOnly/Secure/SameSite-cookie, CSRF-защиту и CSP, а также серверное подтверждение всех прав — UI-проверки не заменяют проверок backend.
